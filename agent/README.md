# 开方智能体（启动即用）

## 方式 A：任意 Chat / Claude / GPT

1. 新建对话，把 [`SYSTEM.md`](SYSTEM.md) 全文设为系统提示（或第一条消息）。
2. 用户发送：主诉 + 体质 + 药房清单。
3. 助手按碑方编号开出加减参考方。

## 方式 B：Grok Bot

侧边栏打开已创建的「中医袁淑芳」Agent，直接发病人情况即可（系统说明与验方库已写入人设）。

## 方式 C：本地脚本（可选）

```bash
# 需要本机已配置 OPENAI_API_KEY 或兼容接口
export SYSTEM_PROMPT="$(cat agent/SYSTEM.md)"
# 再调用你常用的 CLI / SDK，把 SYSTEM_PROMPT 当作 system
```

## 当前选方

网页每次把 `docs/system.md` 整篇当作系统提示词送出。120 首碑方都在这篇里，格式是 `id|分类|病证|体质|方名|药物|用法|标记`。提示词只要求模型「从下方验方库选最贴证的 1～2 首」。程序不打分、不取前几名、不把候选子集单独注入。

程序只有一个字面判断（`localFormulaHit`）：用户原话去掉空白后，是否包含某条病证或方名（至少两个字）。包含，就当碑方对上，不查库外。不包含，才把用户原话前 80 字交给 `POST /v1/formulas/external`，把返回的若干条接在这一轮用户消息后面。同义词不算对上。命中之后，模型仍然看着全部 120 首。

`agent/SYSTEM.md` 是给别的对话粘贴的副本，方剂表与网页相同，少了身世段和危机电话。

## 缺点

- 选哪一首由模型决定。同一主诉可以选出不同编号，程序没有可复核的命中分。
- 120 首每次全进上下文。库再大，后段会被挤掉，编号和药味会串。
- 字面包含不是辨证。「孕吐」对不上「妊娠呕吐」；原话里偶然出现库里的短病证，又会当成已经对上，库外不再查。
- 克数加减、缺药替换、管控药替换都不对照该编号的原文。模型可以写出库里没有的克数。
- 库外排序在摩熵一侧。对不上的条目仍在用户消息里，模型可能照样引用。
- 癫痫、骨伤没有专条，但全库仍在上下文里，模型可能拿别科方硬套。

## 库外方剂

碑方对不上时，网页会先请求 `POST /v1/formulas/external`（摩熵数科中医药方剂，约 10 万首）。密钥只放 Worker secret `BCPM_API_KEY`，不进浏览器。未接通或检索为空时，仍然不准编药名和克数。

开通：<https://open.bcpmdata.com/api/163.html>  
写入：`cd backend && npx wrangler secret put BCPM_API_KEY`

## 最小问诊字段

- 年龄、性别、主诉与病程
- 体质：胖/瘦、怕冷/怕热、痰湿、气郁等
- 月经/白带/胎产史（妇科相关时）
- 药房现有药（没有则按常见饮片库，并标「请对照库存」）
